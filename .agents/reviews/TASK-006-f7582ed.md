### Notes (non-blocking, informational)

**Response body from PUT is ignored after save.**  
`saveEdit` reconstructs `dish` state from the trimmed form values instead of reading the server response body. Acceptable because client sends the same trimmed values it uses to update state. If the server ever normalises data beyond trimming the UI would silently show different data — something to be aware of when evolving the API.

**`if (!id)` guard is dead code.**  
`id` is extracted as `params.id as string` from `useParams()` in a route that can only render when the `[id]` segment is present. The guard at `saveEdit` can never be `true` in production. Harmless, but unreachable.

**No test covers add/remove ingredient paths.**  
AC-03 is satisfied for name/description updates, but adding a new ingredient and removing an existing one via the form buttons are untested. Code paths work correctly (reviewed manually), but gaps could silently regress.
